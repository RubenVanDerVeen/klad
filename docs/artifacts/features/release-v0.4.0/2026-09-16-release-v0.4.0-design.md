# Klad v0.4.0 Release — Design

- **Date:** 2026-09-16
- **Status:** Approved (single-pass execution; user approved push of `main` + tag)
- **Approach:** A — existing tag-triggered CI (`.github/workflows/release.yml`)

## Goal

Cut and publish Klad **v0.4.0** as a public GitHub release with CI-built Windows
NSIS `.exe`, Linux `.deb` (AppImage comes free from the existing bundle targets),
with release notes taken from `CHANGELOG.md`.

## Context

- Repo is now public; last release `v0.3.0` (2026-08-02). 16 commits since,
  notably the Typst single-file live preview feature (→ minor bump) plus fixes.
- `release.yml` already: triggers on `v*` tag push, matrix `windows-latest` +
  `ubuntu-22.04`, builds via `tauri-apps/tauri-action@v0`, files a **draft**
  release named "Klad <tag>".
- Bundle targets already `["nsis", "deb", "appimage"]`; icons and file
  associations already configured. No workflow or config changes needed.
- `gh` CLI is authenticated (`RubenVanDerVeen`, scopes `repo` + `workflow`),
  so verification, notes, and publishing can be done end-to-end.

## Decisions

| Decision | Choice |
|---|---|
| Version | `0.4.0` (SemVer minor: new Typst preview feature) |
| Artifact production | Existing CI on tag push (no local/cross builds) |
| Release commit target | `main` directly (release chore; repo policy allows non-feature work on default branch) |
| Draft publishing | Via `gh` after artifact verification (user authenticated gh for this) |
| Notes source | `CHANGELOG.md` `[0.4.0]` section, applied with `gh release edit` |

## Release changes (single commit, `chore(release): v0.4.0`)

1. **Version bump** `0.3.0` → `0.4.0`:
   - `src-tauri/tauri.conf.json` → `version` (canonical)
   - `package.json` → `version` (sync)
   - `src-tauri/Cargo.toml` → `[package].version` (sync)
   - `src-tauri/Cargo.lock` — regenerated by cargo (run any cargo command);
     include if tracked and changed.
2. **Changelog** `CHANGELOG.md`:
   - Reconcile `[Unreleased]` against `git log v0.3.0..HEAD`: the two `fix`
     commits (dark-mode selection/caret contrast; Typst banner hidden on
     Markdown tabs) go under **Fixed** if not already listed.
   - Convert `[Unreleased]` → `## [0.4.0] - 2026-09-16`.
   - Start a fresh empty `## [Unreleased]` section above it.
3. **Tag & push**: annotated tag `v0.4.0` (`git tag -a v0.4.0 -m "Klad 0.4.0"`)
   on the release commit; push `main` + tag to `origin`.

## Verification

- **Before tagging:** `npm test` and `cd src-tauri && cargo test` pass on a
  clean working tree, `main` up to date with `origin`.
- **After push:** `gh run watch` the `release.yml` run for tag `v0.4.0` until
  conclusion `success`.
- **Draft check:** `gh release view v0.4.0` shows assets including
  `Klad_0.4.0_x64-setup.exe`, `klad_0.4.0_amd64.deb`, `klad_0.4.0_amd64.AppImage`.

## Publishing

1. Extract the `[0.4.0]` section from `CHANGELOG.md` as release notes;
   `gh release edit v0.4.0 --notes "<content>"`.
2. `gh release publish v0.4.0` (flips draft → public).

## Error handling

- CI failure: fix forward on `main`, delete remote + local tag
  (`git push origin :refs/tags/v0.4.0`), re-tag, re-push. Draft releases from
  failed runs do not block a re-run.
- Any verification failure before tagging: stop, report, no tag pushed.

## Out of scope

`.msi` target, publisher/copyright bundle metadata, updater/signing keys,
workflow changes, README changes (install section is already version-generic),
version 1.0.0.
