## Deviations from the plan

1. **Windows CI failure + recovery (Task 3, first attempt FAIL).** Root cause: `src-tauri/tauri.windows.conf.json` declared `bundle.resources: {"target/release/WebView2Loader.dll": ""}`, making the Windows build require a DLL that MSVC builds never produce (`webview2-com-sys` 0.38.2 statically links `WebView2LoaderStatic.lib`). Fix: delete the overlay file (commit `d5928ed`). This **overrode the plan's "no bundle config changes" constraint** — escalated to the oracle (recommended deletion), user approved, and the green CI rerun on the same code path empirically proved the DLL unneeded. Tag deleted both locally and remotely, then re-tagged at the fix commit.
2. **Release-notes encoding.** First notes publish contained mojibake (`â€"`) because PowerShell 5.1 `Get-Content` read UTF-8 as ANSI. Fixed with UTF-8-safe extraction (`[System.IO.File]::ReadAllText` + `gh release edit -F <utf8-file>`). No re-tag, no CI rerun, no commit — release stayed published at the same URL.
3. **`gh release publish` doesn't exist** in the installed `gh` CLI. Used the semantically equivalent `gh release edit v0.4.0 --draft=false`.
4. **Pre-existing CHANGELOG link-ref bug.** The `v0.3.0`/`v0.1.0` refs were hand-crafted and never matched GitHub's anchors. When commit `7bf5747` normalized heading format (`:` → `-`), the reviewer caught that all three refs needed GitHub's actual triple-dash anchors; fixed in `ca28898`.
